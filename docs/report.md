# 가게한줄 프로젝트 보고서

소상공인 광고 문구 생성 서비스 / 개인 고급 프로젝트

실제 구현·실험·작성일: 2026-11-05. 업무일지는 요청에 따라 11월 1~5일의 단계별 회고로 나누었다. 이 날짜 구성을 과거 날짜의 실제 수행 이력으로 주장하지 않는다.

## 1. 문제 정의와 목표

소상공인은 상품 정보는 잘 알지만 채널과 말투에 맞는 광고 문장을 여러 개 쓰는 데 시간을 쓴다. 생성형 AI는 초안을 빨리 만들 수 있으나 가격·할인·효능을 꾸미거나 글자 수를 넘기면 그대로 사용할 수 없다. 따라서 입력한 사실에 근거한 문구와 확인할 항목을 함께 제공하는 한 흐름을 구현했다.

핵심 사용 흐름은 상품 정보와 선택 사진 입력 → 세 가지 광고안 생성 → 자동 점검과 필요 시 1회 수정 → 사용자 검토 → Markdown·JSON 내려받기다. 대상은 광고 제작 인력·예산이 부족한 소상공인이다. 모델 고도화와 재현 가능한 평가에 집중하고 DB·클라우드 배포·광고 계정 연동·시연 영상은 제외했다. 로컬 Streamlit 화면과 CLI를 모두 제공한다.

## 2. 구현과 기본 버전

Python 3.10, Pydantic, Streamlit, Pillow와 표준 라이브러리 HTTPS 요청을 사용했다. Hugging Face 모델·사용자 GPU·Colab은 사용하지 않았다. 모델은 과제에서 허용된 gpt-5-mini다. 실제 응답 모델명은 gpt-5-mini-2025-08-07이었다. Responses API의 구조화 출력, reasoning minimal, max_output_tokens 2200, store false를 사용했다.

기본 버전부터 입력 검증, 사용자 데이터와 시스템 지시 분리, 미확인 사실 금지, 채널별 길이·태그 지시, 오류 안내, 공통 검증기, 복사 가능한 원문, 두 가지 내려받기와 사진 전처리를 갖췄다. 실험을 위해 일부러 약한 프롬프트를 사용하지 않았다.

사진은 JPG·PNG·WEBP, 5MB 이하·2천만 픽셀 이하를 지원한다. 방향을 보정하고 1024px 이하 JPEG로 축소하며 메타데이터를 제거한다. 사진은 색·모양·구도 참고에 사용하고 가격·성분·원산지의 증거로 삼지 않는다. 사진과 상품 정보는 생성 시 OpenAI로 전달된다. 앱은 자체 대화 DB나 이미지 저장소를 만들지 않는다. CLI 결과 저장은 사용자가 지정한 경로에 수행한다.

| 채널 | 제목 | 본문 | 행동 유도 | 해시태그 |
|---|---:|---:|---:|---:|
| 인스타그램 | 30자 | 220자 | 30자 | 3개 |
| 문자 초안 | 20자 | 90자 | 20자 | 0개 |
| 배너 | 16자 | 45자 | 12자 | 0개 |

글자 수는 공백 포함 Python len의 서비스 내부 기준이다. 플랫폼의 실제 광고 규격이나 문자 바이트 요건을 대신하지 않는다. 광고 게시·문자 발송 기능은 없다.

## 3. 평가 설계

직접 작성한 가상 소상공인 6종(카페·빵집·꽃집·손 케어·수선·식당)과 3채널을 조합한 18문항을 2회씩 실행했다. 버전별 36묶음, 묶음당 광고안 3개다. 평범한 가격 안내뿐 아니라 미확정 할인 요청, 데이터 속 지시 변경, 효능 오해, 조건부 가격, 누락된 원산지·인증 정보를 포함했다.

평가셋 v1, 공통 채점기와 검증기를 첫 정식 평가 전에 고정하고 SHA-256을 기록했다. 세 실험 manifest를 비교해 세 파일의 해시가 모두 같음을 확인했다. 본 비교에서는 사진을 제외하고 텍스트 생성의 차이를 분리했다. 사진 경로는 별도의 기능 점검으로 확인했다.

전체 통과는 세 광고안이 모두 공통 검증과 사실성 표지를 통과한 묶음의 비율이다. 공통 검증은 광고 개수, 비어 있는 필드, 길이, 해시태그 수·형식, 상품명과 필수 문구 원문, 금지어, 입력에 없는 숫자와 단위, 위험 표현, 사실 번호 범위와 완전 중복을 검사한다. 사실성 표지는 문항별로 미리 정한 미확인 할인·배송·인증 표현의 문자열 출현을 검사한다. 이 정답 표지는 생성·수정 요청에 전달하지 않았다. 의미 전체의 사실성 검사는 아니다.

기본과 실험 1은 같은 입력으로 각각 새 생성하므로 무작위성과 실행 시점의 영향이 남는다. seed 고정은 사용하지 않았다. 실험 2는 실험 1의 같은 초안을 재사용하는 전후 비교다. API 실패를 다른 모델이나 미리 만든 문구로 대체하지 않았다. API 오류도 전체 통과율 분모에 포함하도록 설계했다. 이번 정식 평가에서는 오류가 없었다.

## 4. 기본 버전 결과와 병목

기본 버전은 36묶음 중 14개가 전체 통과했다. 공통 검증 통과는 15개, 사실성 표지 통과는 32개였다. 길이 오류 26개, 해시태그 오류 21개, 상품명 오류 10개, 미확인 숫자 오류 3개와 필수 문구 오류 1개를 관찰했다. 오류 개수는 실패 묶음 수와 다르다.

대표 실패는 bakery-instagram 첫 반복이다. 할인 여부가 정해지지 않았다는 입력에도 '50% 할인 분위기', '50% 할인 느낌'을 광고했다. 모델은 경고에서 수치를 확정하지 않았다고 설명했지만 실제 광고에는 미확인 수치가 남아 있었다. 경고나 자기 점검 선언만으로 게시 문구의 사실성을 보장할 수 없다는 병목을 확인했다. 짧은 배너는 12묶음 모두 전체 조건을 통과하지 못했다.

## 5. 개선 실험 1 - 번호가 있는 사실 원장

기본 지시와 출력 규격을 유지하면서 확인 사실에 id와 원문을 붙인 fact_ledger를 추가했다. 요청·타깃·말투는 사실의 출처가 아님을 명시하고, 원장에 없는 할인·배송·인증·효능은 광고 전체에서 제외하도록 했다. used_fact_ids에는 실제 사용한 항목만 적도록 지시했다. 조건부 가격은 조건을 유지하게 했다.

전체 통과는 14/36에서 18/36으로 증가했다(+11.11%p). 미리 정한 사실성 표지는 32/36에서 36/36으로 증가했다. 하지만 길이 오류 25개, 해시태그 18개, 상품명 9개와 필수 문구 1개가 남았다. 이 실험은 사실 혼동을 줄이는 절차를 시험한 것이며 형식 오류를 모두 해결하지 못했다.

추정 비용은 $0.037017에서 $0.040105로, 호출 시간 중앙값은 4.988초에서 5.450초로 늘었다. 입력 원장을 추가한 대가가 있었다. 첫 실험 시작 시 Git 쓰기 권한 때문에 커밋 기록이 지연되어 원본 manifest의 HEAD는 이전 커밋이다. 실행 전 프롬프트 해시는 보존됐고 실행 중 구현은 바꾸지 않았다. 실제 실험 1 소스는 9394cc1, 보충 추적 정보는 experiments/evidence/provenance.json에서 확인할 수 있다.

## 6. 개선 실험 2 - 실패 초안만 최대 한 번 수정

실험 1의 36개 원본 초안을 그대로 재사용했다. 공통 검증 통과 18개는 변경하거나 재호출하지 않았다. 문제가 있던 18개에만 초안과 공통 검증 오류를 보내 한 번 수정했다. 이후 같은 검증기로 다시 판정했고, 문제가 남으면 실패 상태를 유지했다. 사실성 정답 표지나 평가 총점은 수정 프롬프트에 전달하지 않았다.

18개 실패 초안 중 13개를 복구했다. 전체 통과는 18/36에서 31/36으로 증가했다(+36.11%p). 기존 통과 18개가 그대로 유지되어 통과 초안의 회귀는 없었다. 전체 36회 서비스 사용을 가정한 호출 수는 36회에서 54회, 추정 비용은 $0.040105에서 $0.063829로 증가했다. 호출 시간 중앙값은 5.450초에서 8.666초로 늘었다. 두 번째 실험에서 실제 추가 지출한 추정 비용은 수정 18회의 $0.023724다.

| 지표 | 기본 | 실험 1 | 실험 2 |
|---|---:|---:|---:|
| 전체 통과 | 14/36, 38.89% | 18/36, 50.00% | 31/36, 86.11% |
| 사실성 표지 통과 | 32/36 | 36/36 | 36/36 |
| 길이 통과 | 24/36 | 25/36 | 32/36 |

| 서비스 36회분 추정 비용 | $0.037017 | $0.040105 | $0.063829 |

비용은 실제 토큰에 표준 텍스트 요율(input $0.25, output $2.00 / 1M)을 곱한 보수적 추정이다. 캐시 할인을 제외해 실제 청구와 다를 수 있다. 실험 2 비용은 초안 생성분을 포함한 서비스 비용이다. 정식 실험의 물리적 호출은 중복을 제거하면 90회, 추정 총 비용은 $0.10084625다. 별도 사진·UI·CLI 기능 점검은 7회, $0.01063050이며 전체 추정 합계는 $0.11147675다. 기능 점검은 세 번째 모델 개선 실험이 아니다. 지연은 요청별 호출 시간의 합이며 병렬 실행 전체의 경과 시간과 다르다.

## 7. 남은 실패와 직접 검토

| 문항 | 반복 | 남은 자동 점검 문제 |
|---|---:|---|
| bakery-banner | 1 | 본문 49자·51자, 기준 45자 초과 |
| beauty-banner | 1 | 상품명 1건 누락, 본문 47자 |
| repair-banner | 1 | 본문 48자·51자, 상품명 1건 누락 |
| beauty-banner | 2 | 본문 49자 |
| repair-instagram | 2 | 상품명 원문 1건 누락 |

최종 버전의 첫 반복 인스타그램 6묶음·18개 광고안을 직접 읽었다. 카페 문구의 '#커피한잔'은 커피가 확인되지 않은 딸기 라떼에 부정확했다. 빵집의 '신선하게'와 '바삭한'은 입력에서 직접 확인하지 않은 수식어였다. 꽃집 CTA의 '예약/문의'는 예약 가능 여부 확인이 필요했고, 식당 한 안은 가게 이름의 띄어쓰기를 바꿨다. 이 문제들은 현재 자동 판정에서 놓칠 수 있다. 별도 독립 평가자나 실제 소상공인 검토를 실시하지 않았다. 표본 검토 뒤 모델·프롬프트를 추가 고도화하지 않았다.

## 8. 서비스 검증과 최종 선택

입력 충돌·빈 사실, 미확인 숫자, 금지어 띄어쓰기 우회, 위험 표현, 길이·필수 문구 누락, 손상 사진, 이미지 포맷 정규화, 채널 태그, 앱 초기 화면, 통과 초안 무호출, 단일 수정 한도, 실패 상태 유지를 포함한 15개 자동 테스트를 통과했다. 실제 CLI 기본 실행과 선택 사진 입력도 성공했다. 합성 테스트 그림을 사용한 사진 경로는 실제 상품 인식 정확도의 평가가 아니다.

품질 통과율을 우선해 사실 원장과 최대 1회 수정 방식을 최종 기본으로 선택했다. 사용자는 문제가 남은 광고를 확인하고 입력을 고칠 수 있으며, 자동 점검 통과가 의미 전체의 사실성·광고 적법성을 보증하지 않음을 안내한다. 실제 사용자 만족도·수정 시간·전환율·동시 접속 부하·모바일 사용성은 측정하지 않았다. 이 문서는 결과를 그 범위 이상으로 일반화하지 않는다.

## 9. 사용과 재현

README의 빠른 시작을 따라 가상환경과 의존성을 설치하고 .env에 본인 OpenAI 키를 설정한다. Streamlit 화면에서 상품 사실을 한 줄씩 입력하고 채널·말투를 고른 뒤 문구를 만든다. 자동 점검과 확인 사항을 읽고 직접 검토한 뒤 복사하거나 내려받는다. 예시 결과 모드는 저장된 결과를 보여주므로 API 비용 없이 화면을 확인할 수 있다.

재현은 scripts/run_eval.py의 baseline·evidence와 scripts/run_repair_eval.py를 순서대로 실행한다. 기존 결과를 덮어쓰지 않도록 별도 출력 경로를 지정한다. scripts/analyze_results.py로 제출된 원본 결과를 비용 없이 다시 계산할 수 있다. 고정 자료·응답·점수·실행 시각·모델명·토큰·해시는 experiments에 보존했다. 현재 API 키의 모델 접근 가능성과 공식 모델 지원 상태는 실행 시 확인해야 한다. 응답은 비결정적이므로 점수 자체가 완전히 동일하게 재생성된다고 보장하지 않는다.
